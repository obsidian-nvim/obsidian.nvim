# Plan: retire `api.lua` as an internal dependency

## Decision

Keep `require('obsidian.api')` and `require('obsidian').api` working in 3.x. Make `api.lua` a compatibility facade, not the place core code goes to find an operation. Move behavior to its owner, migrate callers to that owner in the same PR, and keep the original name, arguments, results, and defaults at the facade. A clean extraction should remove a dependency on `api`, not just move its body into `editor/api.lua`.

Base the first PR directly on `main`. It doesn't need the LSP-dispatch branch, Markdown-query branch, or string-path branch. The cursor PR can follow `refactor/markdown-reference-query` once it lands; if it hasn't landed, extract the adapter without inventing a second reference-eligibility rule. The path migration stays separate: keep current `Path` representations at existing interfaces throughout this refactor.

## PR 1 — extract leaves and stop reverse imports

The first patch should be boring: move platform, runtime and synchronous prompts, and route trivial aliases straight to their existing owners. If needed, split the platform/runtime changes from the prompt call-site sweep; both are independently reviewable.

1. Before moving the code, capture prompt cancellation vs empty input and custom confirmation labels. Keep discovery results, timeout and unknown commit handling unchanged. Check that importing `platform` and `editor.prompt` works before `setup()` and does not import the root, picker, note, or LSP.
2. Migrate `path.lua`, clipboard/platform callers, and health to the platform owner; migrate renderer/picker discovery and help setup/completion to runtime. Replace uses such as `api.dir`, `api.is_attachment_path`, and `api.resolve_attachment_path` in core with their real owners.
3. Migrate prompt users to the shared prompt module. Many tests override `api.input`, `api.confirm`, `api.get_os`, or `api.get_plugin_info` to drive interaction. Update the affected tests in the same patch, using the owning adapter or a child-Neovim behavioral test, and restore overrides with test cleanup. Don't add reverse links just to keep arbitrary monkey-patching of `api` working. Explicitly call out the difference between preserving call signatures and preserving an undocumented interception point.
4. Leave `api` forwarding those names. Preserve per-function annotations/deprecations where consumers rely on them. Verify `require('obsidian').api` is still the same facade as the direct require.

**Done:** Low-level `Path:is_absolute()` no longer loads `api` for OS detection. Changed consumers don't go through old aliases. Prompt/discovery/clipboard tests and the old calling surface pass. No workspace or cursor logic rewritten.

## PR 2 — separate workspace lookup from activation

1. Extract `find_workspace` and effective options first. Make the lookup use an explicit list of workspaces at the core seam; the current session list is a default at the caller/facade. Preserve **most-specific `ws.root`, lenient resolution**, including nonexistent paths. Keep `Workspace.find` intact: it does **first matching `ws.path`, strict existing directory** for startup; they aren't interchangeable.
2. Move `resolve_workspace_dir` into a clearly named routing helper. Keep the distinction between an explicit path and no path, the `obsidian_buffer` gate for inspecting the current buffer, the active workspace fallback, and the legacy `Obsidian.dir` fallback. Effective options for a non-active workspace must not mutate `Obsidian.opts`; preserve workspaces with different override settings.
3. Extract template-directory lookup before moving note admission. Preserve the existing absolute/relative search order and directory existence check. Move note membership/`current_note` next. Don't silently unify the extension-case/ignore differences with `filetypes.lua`, search, or `BufEnter`; those are separate policy changes.
4. Migrate callers in groups (search/cache, note/attachment, startup/editor). Pass explicit source context where already available; do not undertake a general async-context migration here. `Workspace.set` retains all activation, cache/UI/sync setup, and events.

**Tests:** Nested `root` and `path` workspaces, duplicate roots/ordering, nonexistent files, non-note files, inactive workspace overrides, templates and outside paths, and an unrelated current buffer. Compare the old wrapper and the new owner where fallback behavior is part of the contract. Assert read-only lookups don't trigger workspace activation. Track `search.find_notes` not forwarding `opts.dir` and `resolve_note_async` mixing explicit roots with active options separately; don't bury fixes in moves.

## PR 3 — cursor, selection, and open adapters

Do cursor/selection and opening as separate patches if they touch many callers.

- Cursor: take a buffer snapshot once; use document-aware reference eligibility (and preserve standalone lexical parsing for incomplete completion elsewhere). Adapt LSP `Position` via `Pos` in LSP handlers, not inside the syntax query. Migrate smart action and other current-window conveniences while keeping their key precedence. Characterize `cursor_tag`'s frontmatter fallback before changing it: it currently reads `<cWORD>` from the active window even with an explicit position. Move it with parity first or fix it in a focused follow-up using source tag ranges; don't silently replace inline-frontmatter recognition with YAML-only recognition. Add a non-current-buffer test for the new explicit-position seam.
- Selection: keep live-vs-last-mark selection semantics, exit behavior, strict mode, reversed selections and UTF-8 inclusive-end conversion. Offer a normalized `Range` for linear selections when callers are ready; don't pretend a blockwise selection is one continuous range, or break the legacy `lines/selection/csrow/...` return table. Existing visual selection and link-word fixtures are the baseline.
- Opening: pass `{ path, cmd, pos?, highlight? }` from `Note:open` and actual adapter sites, rather than funneling internal callers through a quickfix entry. First preserve `Note:open`'s live-buffer heading/block resolution, scheduling, and callback. Entry conversion stays at the picker/legacy adapter (quickfix 1-based fields, optional `Range` or UTF-8 LSP range, existing precedence). Leave old default command strings, `drop` reuse, non-current buffer behavior, and empty/EOF highlight handling unchanged. Use child tests for window reuse/split, file names with spaces, and blink extent/cleanup.

**Done:** LSP and picker data stop leaking into the new editor interface. Syntax still belongs to the document query, not the buffer adapter. Legacy callers and their tests see the old tuple and entry behavior.

## PR 4 — format links, then move missing-target creation

1. **Format first.** Take target, vault-root policy, explicit source directory, label/style/format at the new seam. Keep `absolute` meaning vault-relative, `relative` base precedence, shortest/basename behavior, embeds/aliases/fragment rendering and custom formatter callbacks. The new internal operation shouldn't need to mutate its argument or `Obsidian.buf_dir`; if compatibility requires the current `api.format_link` argument mutation, keep it at the wrapper until a versioned change. Migrate `Note:format_link` and picker mappings. Test explicit source directory with an unrelated active window and both wiki/Markdown styles. Don't fold attachment formatting or the separate link-resolution refactor into this move.
2. **Extract the cache-picker workflow first.** `api.create_new_note` is not a primitive constructor. It prompts for regular/template/unique creation, rewrites a cursor link and/or references, and reports an LSP location. Use an internal result with the created `Note` and explicit source/reference ranges; translate to the existing callback shape at the facade and let the cache picker open the note without an LSP round trip. Capture the request's source and relevant workspace at the start. Keep existing result/callback behavior on cancel/failure at the old facade. If a unified result-on-cancel contract is useful, make that a separate explicit decision.
3. **Don't delete the duplicate under `_definition.lua` until both behaviors are covered.** It also prompts and rewrites one link, but the cache picker variant performs source-relative `./` and `../` placement and can rewrite multiple files. Verify parity before pointing both at a shared worker; keep LSP definition/navigation behavior unchanged in this PR. Avoid making `actions` and the workflow depend on each other: call the owner of note creation/template selection, and have `actions` forward there when that smaller extraction is needed.
4. **Preserve write semantics.** Current reference rewriting uses each source dir, sorts edits back-to-front per file, skips stale text, modifies loaded buffers without writing them, and rewrites unloaded files without buffer write hooks. Keep those invariants. Supplying `dir` explicitly eliminates the current save/overwrite/restore of `Obsidian.buf_dir`; add a regression that catches incorrect relative links when the current window and two references are in different directories. Test no writes on cancellation, template and unique paths, label/fragment/embed preservation, and stale entries. Reuse existing edit machinery only if it can preserve the loaded/unloaded and callback contracts; don't invent a generic transaction layer here.

## Compatibility and exit criteria

- For 3.x, preserve public callability and shapes, documented aliases (`smart_action`, attachment aliases), root access and existing deprecation messages. Keep lazy forwarding to real owners when needed to avoid making `require('obsidian.api')` load every feature. Internal code must not import the facade to save an import. Any remaining internal exception needs a named reason, not a new catch-all module.
- Tests should exercise the new owner where that is now the seam, while a small compatibility suite calls the old surface. Use in-process tests for formatting/geometry, temp files for path and rewrite behavior, and child Neovim for prompt/window/autocmd/LSP state. Run full `make test`, changed-file StyLua/Selene, and compare `make types` with the base checkout; use the supported Neovim minimum in CI. Preserve testable explicit inputs rather than adding a mockable global context bag.
- Completion means **`api.lua` has forwarding and legacy shape conversion only**, no independent filesystem/editor/workflow policy; core imports its owners; and importing a leaf doesn't load the root facade, editor UI, or LSP unless that leaf actually needs it. Don't set a line-count target.
- 4.0: choose the supported scripting names, publish migration examples, annotate the lazy root facade, and remove only the shims announced for removal. Removing `api` itself, changing path types, rewriting workspace lifecycle, moving every file, and changing UI/LSP behavior are not requirements for landing the extraction series.
